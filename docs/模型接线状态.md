# 数据模型接线状态

> 需求文档定义了 19 个实体，本表标注每个 Prisma 模型的接线状态，避免把「预留扩展点」误判为「已实现功能」。

## 已接线（功能可用）

| 模型 | 用途 | 接线位置 |
|---|---|---|
| `Project` | 项目主表 | 项目 CRUD API、详情页 |
| `FloorplanAsset` | 户型图资产（上传/分流/识别快照） | floorplans / parse / confirm API |
| `Opening` | 门窗开口 | parse 路由创建（含 swingJson 门弧证据） |
| `DetectedRoom` | 识别出的房间 | parse 路由创建、confirm 确认、quantity 计价 |
| `RoomAdjacency` | 房间邻接表 | parse 路由创建（门洞连接） |
| `DesignScheme` | 设计方案（overlay 覆盖集） | schemes API、design 页 |
| `QuantityLine` | 工程量明细 | quantities API |
| `BudgetItem` | 预算明细 | budget API |
| `AiChangeProposal` | AI 变更提案 | proposals API |
| `ClientShareLink` | 客户分享链接 | share API |
| `ClientFeedback` | 客户反馈 | share/[token]/feedback API |
| `ClientApproval` | 客户确认 | share/[token]/feedback API |
| `TourRoute` / `Waypoint` / `TourScene` | 漫游路径与全景缓存 | tour API |
| `ReferenceImage` | 参考图 | references API |

## 预留未接线（扩展点，暂以 TS 常量/JSON 承担）

| 模型 | 说明 | 当前替代实现 |
|---|---|---|
| `WallSegment` | 墙段（中线+厚度） | 墙体以 `wallLoops` JSON 多边形矢量表达（`FloorplanAsset.parseJson`） |
| `Material` | 材质库（规格/价格） | `src/lib/materials.ts` TS 常量 |
| `DesignStyle` | 风格库 | `src/lib/styles.ts` TS 常量（16 套） |
| `RecognitionItem` | 识别项（要素级证据） | 识别结果直接落 `DetectedRoom` + `Opening` |
| `SpaceElement` / `ElementLayer` | 空间要素 + 分层（结构/基层/装饰/面层） | 以 `DesignScheme.overlayJson` 的四目标面（floor/wall/ceiling/cabinet）表达 |
| `DesignVersion` | 设计版本快照 | 未做版本管理，仅有主方案 `isPrimary` |
| `GenerationJob` | 异步任务队列 | 识别/渲染同步完成（本地运行），未做异步队列 |
| `ClientSession` | 客户访问会话 | 仅 `ClientShareLink.viewCount` 计数，未记录 UA/IP/时间 |
| `ClientFeedbackAttachment` | 反馈附件 | 反馈仅文字，未做附件上传 |

## 说明

- 「预留未接线」不代表缺失：对应能力已由更轻量的方式（TS 常量 / JSON 字段 / 同步计算）承担，四个核心模块功能完整。
- 若后续需要「界面自定义风格」「版本管理」「异步渲染队列」等能力，再按上表把这些模型从预留升级为接线。
