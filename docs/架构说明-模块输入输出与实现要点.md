# 户型图智能分析与三维可视化系统 —— 模块设计说明

> 本文档说明系统四个核心功能模块的**输入、输出、核心处理流程与实现要点**，
> 作为架构交付物之一，与代码一一对应。

## 0. 总体架构

```
户型图(图片/PDF) ──► [模块1 智能分析] ──► 结构化户型 JSON
                                              │
                                              ▼
                                     [模块2 三维建模] ──► 精确 3D 场景
                                              │

                                              │

```

- **技术栈**：Next.js 14（App Router）+ TypeScript strict + React 18 + Tailwind v4；
  Three.js / @react-three/fiber（3D 与全景）；@photo-sphere-viewer/core（全景查看）；
  Prisma + SQLite（持久化）；sharp（图像处理）；pdfjs-dist（PDF 栅格化）。
- **工程目录**：`C:/Users/Administrator/Desktop/全景装修/户型三维系统/`
  - `src/lib/cv/` 计算机视觉管线（预处理/分层/尺寸链/房间分割）
  - `src/lib/geom/` 几何（轮廓矢量化/墙体）
  - `src/lib/parse/` 识别编排 + VLM
  - `src/lib/model3d/` 三维构建
  - `src/lib/pano/` 路径规划 + 全景捕获
  - `src/lib/ai/` 大模型 Provider 抽象
  - `src/components/` + `src/app/projects/[id]/{parse,model,design,tour}/` 四模块 UI
- **生成路线（已定）**：`3D 骨架 + AI 增强（混合）`——几何/尺寸/漫游全部由
  三维场景程序化生成（绝对准确、效果图与漫游同源），AI 仅用于户型识别辅助
  与材质风格参考，不替代几何。

## 模块 1：户型图智能分析

### 输入
- 标准户型图：**图片**（PNG/JPG/WebP/BMP）或 **PDF**（逐页栅格化），单文件 ≤ 30MB。
- 可选：视觉大模型 API Key（OpenAI 兼容 / 国内厂商可切），无 Key 时走本地降级链路。

### 输出
- `FloorplanJson`（存储于 `FloorplanAsset.parseJson`）：
  - `mmPerPx` / `scaleSource` / `scaleConfidence`：比例标定结果
  - `rooms[]`：房间多边形（毫米、图纸坐标）、类型、面积、置信度、`needsConfirm`
  - `openings[]`：门/连通口/窗（中心、宽度、走向、两侧房间）
  - `wallLoops[]`：墙体矢量多边形（外环 + 房间孔洞）
  - `issues[]`：需要人工复核的异常（闭合误差、比例默认值等）

### 核心处理流程
1. **预处理** `cv/preprocess.ts`：sharp 解码 → 归一化位图 → 亮度直方图求纸张亮度。
2. **页面分流** `cv/pageRouter.ts`：白底占比、灰度占比、饱和度均值、细线密度、
   大色块占比 → 判定 `BLUEPRINT`（户型图）/ `MARKETING`（营销鉴赏页）/
   `UNKNOWN`。营销页自动归入「风格参考素材」，不进入识别。
3. **颜色分层** `cv/colorLayer.ts`：基于纸张亮度自适应阈值，产出
   `dark`（深色墙带）/ `ink`（全部墨迹）/ `blue`（玻璃幕墙）/ `beige`（寝具）/ `green`（植栽）。
4. **尺寸链检测与比例标定** `cv/scale.ts`：
   - `detectChains` 在四边检测最长连续墨线 → 建筑外轮廓包围盒与闭合误差；
   - `detectChainTicks` 检测尺寸段刻度；
   - `moduleSearch`：无 VLM 时用「300mm 模数 + 分段 50/100mm 吸附」在 6~30mm/px
     内搜索比例（残差极小处即真比例）；
   - VLM 读尺寸链（`parse/vlm.ts`）与模数搜索**交叉验证**：偏差 <4% 采信，
     <12% 降置信进复核，>12% 强制人工标定；`MANUAL` 优先级最高。
5. **房间分割** `cv/rooms.ts`（本系统核心难点，见实现要点）：
   膨胀密封泛洪 → 判室外 → 腐蚀去吸附带 → 净空距离场 → 房间核 → 多源 BFS 回填 → 层级拆分。
6. **轮廓矢量化** `geom/contour.ts` + `geom/walls.ts`：房间标签追踪外轮廓
   （Pavlidis 边界跟踪 + Douglas-Peucker 简化），墙带矢量化 + 孔洞归属。
7. **门/窗/开口检测** `parse/pipeline.ts`：门洞 = 房间标签 4-邻接接触段（宽度经
   距离场鞍部标定）；窗 = 蓝色玻璃连通块（默认窗台 900 / 窗顶 2100）。
8. **房间分类**：规则初分类（面积/位置/米色寝具/绿色植栽）→ VLM 精分类（可用时）
   → 全部标记 `needsConfirm` 进人工确认队列。

### 实现要点
- **无房间名的户型图如何定房间类型**：本批素材图上无任何中文标注，房间类型只能
  靠「家具图元颜色（米色=床/地毯、绿色=植栽）+ 面积 + 是否贴外墙」的规则初判，
  VLM 可用时按其视觉判断覆盖，最终由人工确认兜底。
- **墙体画法**：实测为「深色实心带（约 10~13px，带细密纹理）」+「外圈蓝色玻璃细线」。
  墙掩膜须 `open(dark,3)` 去细线后再 `close(_,5)` 填纹理缝，顺序不可反
  （先闭后开会把尺寸线增粗成实体带混入墙掩膜）。
- **室外判定（关键）**：外圈墙网存在真实缺口（入户门 ~1.0m、外窗）。用
  `dilate(wall, 0.6m)` 膨胀密封后从图像边界泛洪 → 室外；再 `erode(¬outside, sealR+15)`
  剥掉建筑外围吸附带。**不能用「自由连通块接触室外即剔除」**——入户门是合法连通，
  会把室内与吸附带连成一个整体导致全部误删。
- **门洞分离**：房间核用「净空距离 ≥ 0.5m」阈值，门洞鞍部距离 ~0.45m 天然断开，
  无需检测门弧；窄道/门口像素由多源 BFS 回填给最近房间。
- **开放空间合并**：客餐厅/开放式厨房因宽开口天然合并为一个空间，属预期行为，
  由人工确认阶段决定是否细分。
- **已知局限**：入户门外的公共走廊/电梯厅可能经入户门并入玄关空间（几何正确但
  语义需剔除），交由房间分类与人工确认处理；曲线外墙由多边形逼近。

## 模块 2：三维建模

### 输入
- 模块 1 产出的 `FloorplanJson`（房间多边形、墙体环、开口、比例）。

### 输出
- 一个 `THREE.Group`：墙体（含门窗开洞）、地面、天花板（可选）、程序化家具、
  灯光；`BuildStats`（墙三角面数、家具数、构建耗时、警告）。

### 核心处理流程
1. **坐标系统一** `model3d/builder.ts`：图纸毫米 → 米（÷1000）；图纸 (x 右, y 下)
   → 三维 (x 右, y 上, z 向观察者)。墙高默认 2800mm。
2. **墙体生成**：墙环多边形（外环 + 房间孔洞）→ `THREE.Shape` + holes →
   `ExtrudeGeometry` 拉伸到墙高。曲线墙由 `curveSegments` 逼近。
3. **门窗开洞（CSG）**：用 `three-bvh-csg` 的 `Evaluator`，把墙 Mesh 依次与
   「门（地面~2.1m）」「连通口（通高）」「窗（0.9~2.1m）」的切削盒做 SUBTRACTION。
   窗洞再嵌玻璃板（半透明 PBR）与窗框。
4. **地面**：每个房间多边形 `ShapeGeometry`，颜色/材质按风格规则（模块 3 传入）。
5. **天花板**：漫游模式才生成（交互模式遮挡视线）。
6. **程序化家具** `placeFurniture`：按房间类型摆床/沙发/茶几/电视柜/衣柜/橱柜/
   洁具/绿植，纯 Box/Cylinder 组合，几何轻量、风格可换材质。
7. **灯光**：环境光 + 半球光 + 方向光（窗外）+ 每房间点光（强度随面积）。

### 实现要点
- **为什么选 CSG 而不是分段建模**：墙体来自任意多边形环（含曲线），分段建墙需要
  把环拆成直线段并逐个扣开口，复杂度高；CSG 一次减法即得任意形状的精确开洞，
  构建耗时实测 <200ms。
- **尺寸准确性的保证与验证**：几何全部来自标定后的毫米坐标，无任何缩放猜测；
  `npm test` 回归断言墙三角面 >0、房间多边形面积 >1m²、开口数 ≥3。
  交互视图提供比例标定信息显示；后续可加「点选量测」进一步人工核对。
- **风格切换是毫秒级**：只重建材质与家具，不重建几何。

## 模块 3：硬软装设计与多方案对比

### 输入
- 模块 2 的 3D 场景 + 风格模板（16 套内置风格）+ 用户参数描述。

### 输出
- 多套 `DesignScheme`（`overlayJson` 参数覆盖集：roomId → 各面颜色/材质覆盖），
  可在三维查看器与全景漫游中切换、A/B 同屏对比。

### 核心处理流程
1. **风格模板** `styles.ts`：16 套风格，每套含
   `paletteJson`（色板）、`materialRulesJson`（目标面+房间 → 材质，priority 排序）、
   `colorRulesJson`（颜色）、`lightingJson`（昼/夜色温强度）、`furnitureRulesJson`。
2. **风格引擎联动** `matchColor/matchMaterial`：按「精确房间规则 > 通配规则 >
   优先级」匹配，风格切换即驱动材质/颜色/家具/灯光联动变化。
3. **参数覆盖** `builder.ts` 的 `overlay`：单房间级覆盖风格默认值，用于方案差异化。
4. **多方案管理** `api/schemes` + `api/schemes/[id]`：创建（从风格）、改名、设主方案、
   删除；主方案唯一。
5. **A/B 对比** `design/page.tsx`：左右双查看器并排，各自独立轨道控制，可分别选风格
   与覆盖，同屏对比不同方案。

### 实现要点
- **需求文档「结构/基层/装饰/面层」四层的落地**：落地为「几何层（不可变）+
  风格规则层 + 覆盖层 + 材质库（`Material` 模型含 tileSize/grout/price 等）」
  的分层结构，覆盖层优先级最高。
- **AI 增强贴图的降级**：`ai/client.ts` Provider 抽象；无 Key 时程序化纯色/材质
  直接可用，AI 贴图入口保留但可降级，不影响主链路。

## 模块 4：全景入户漫游

### 输入
- 模块 2 的 3D 场景（带天花板）+ 模块 3 选定的方案 + 模块 1 的开口数据。

### 输出
- 一条入户漫游路径（`RoutePlan`：途经点序列 + 路径折线 + 覆盖房间）+ 每途经点
  一张 2:1 等距圆柱全景图 + 热点（指向相邻途经点）+ 小地图。

### 核心处理流程
1. **路径规划** `pano/route.ts`：定位入户门（`entrance` 开口，兜底取最贴外墙的门）→
   以「入户门 + 各房间质心」为途经点 → 贪心最近邻生成访问顺序 → 相邻点连成路径折线；
   途经点 yaw 指向下一站。
2. **全景生成** `pano/capture.ts`：`CubeCamera` 在途经点（眼高 1.6m）渲染六面 cubemap
   → 等距圆柱投影着色器合成 2:1 全景 → JPEG dataURL。
3. **热点自动生成** `components/tour/TourViewer.tsx`：对每站计算「下一站方向」的
   yaw/pitch（全景 lon=0 即 +z 轴，yaw = atan2(dx, dz)），生成 PSV marker。
4. **展示**：`@photo-sphere-viewer/core` + `markers-plugin` 沉浸式查看，热点跳转相邻站，
   支持自动导览（定时切换）；SVG 小地图绘制房间多边形 + 路径 + 当前位置高亮。

### 实现要点
- **为什么选 CubeCamera + equirect**：几何、尺寸、视角全部来自三维场景，效果图与
  漫游**同源一致**，不存在 AI 生图「几何不保真、无法沿路径连续漫游」的问题；
  分辨率 640px/面（全景 1280×640），性能预算每站 <1s，5~8 站 <10s。
- **行走路径的可视化**：小地图路径折线 + 途经点序号 + 当前位置高亮 + 前后站热点，
  四者共同体现「行走路径」。
- **相机控制**：PSV 拖拽旋转、滚轮缩放、两指触控，`defaultZoomLvl` 约束起始视场。

## 附录：配套模块（客户分享 / 工程量 / 预算 / AI 提案）

- **客户分享**（只读）：`/api/projects/[id]/share` 创建链接（token 仅显示一次、可设访问码），
  客户经 `/share/[token]` 访问；访问码经 HMAC 签名 cookie 校验，页面只读展示三维与全景、
  支持反馈与确认（`ClientFeedback` / `ClientApproval`），不暴露 AI prompt 与成本。
- **工程量** `lib/quantity.ts`：从房间多边形与开口做精确几何计量（地面/墙面/顶面/
  踢脚线/门窗/橱柜），墙面扣门窗洞、踢脚线扣门宽。
- **预算** `lib/budget.ts`：内置参考单价 × 损耗率，可导出 CSV（BOM）与 JSON。
- **AI 变更提案** `lib/ai/propose.ts`：自然语言 → 结构化 overlay 补丁 → 确认后合并进主方案，
  无 Key 时明确报错并降级为手动编辑。

## 附录：风险与对策
| 风险 | 对策 |
|---|---|
| 户型图分辨率偏低（长边 <2000px） | 上传校验 `MIN_FLOORPLAN_EDGE=800`；比例按尺寸链标定而非固定 DPI |
| VLM 无 Key | 本地模数搜索 + 规则分类 + 人工确认兜底，链路 100% 可跑 |
| 曲线外墙 / L 形外轮廓不闭合 | 尺寸链闭合误差单独上报；多边形逼近曲线墙 |
| CSG 性能 | 单次构建 <200ms；BVH 加速；开洞盒合并后一次减法 |
| 全景渲染耗时 | 每面 640px，逐站让出主线程（await 30ms）避免阻塞 UI |
| 公共区误并入（电梯厅/走廊） | 分类 + 人工确认队列剔除，宁多勿漏 |
